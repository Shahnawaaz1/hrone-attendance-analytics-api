# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `POST /employees` (`create_employee`) | Missing validation that `shift_start != shift_end` | Input `shift_start="09:30"`, `shift_end="09:30"` returns 201 instead of 422 | Added check in `create_employee` returning HTTP 422 when `shift_start == shift_end` |
| 2 | `POST /employees`, `POST /attendance/punch-in` | Concurrency race condition: `find_one` followed by `insert_one` | Concurrent identical requests both pass `find_one` and create duplicates | Switched to atomic `insert_one()` catching `DuplicateKeyError`, backed by unique indexes created at startup |
| 3 | `POST /attendance/punch-in`, Helpers | `punched_at` not truncated to whole seconds | Truncated seconds show up as milliseconds in `created_at` or `punch_in` | Added `truncate_to_seconds(dt)` before storing timestamps |
| 4 | `POST /attendance/punch-in`, Helpers | Ignored timezone, used naive local `datetime.now()` | `datetime.now()` treated as UTC by PyMongo, shifting times by 5.5 hours | Replaced with `datetime.now(timezone.utc)` and explicit `IST` conversions |
| 5 | `POST /attendance/punch-in` (`get_attendance_date`) | Overnight shift date assignment bug | Punch-in at 05:00 for a 22:00-06:00 shift incorrectly sets `date` to today instead of previous calendar day | Added `get_attendance_date` with previous-day logic for times < `shift_end` |
| 6 | `compute_late_minutes` | `start` date logic breaks when `punch_in` is on a different calendar day | Calculation produces wrong late minutes or crashes on overnight shifts | Fixed to construct shift start using the resolved attendance `date` and `shift_start` time |
| 7 | `compute_late_minutes` | Late-minute grace period boundary defect (floored before grace comparison) | Arrival at `09:40:01` for a `09:30` shift produced 0 late minutes instead of 10 late minutes | Evaluated grace period against exact elapsed seconds (`> 600`) before integer division (`elapsed // 60`) |
| 8 | `GET /employees`, `GET /attendance` | `total` incorrectly counts entire collection | Passing a query param (e.g., `department="HR"`) gives wrong `total` count in pagination | Changed `count_documents({})` to `count_documents(q)` using the active query filter |
| 9 | `GET /attendance` (`list_attendance`) | In-memory sort and pagination, and missing compound index for cursor sort | Sorting in Python causes high memory usage and explain queries reveal `COLLSCAN` / memory sort | Created compound index `(date: -1, emp_code: 1)` and delegated sorting/pagination directly to MongoDB `.sort().skip().limit()` |
| 10| `POST /attendance/punch-in`, `GET /attendance` | Response serialization violates OpenAPI schema | Document `_id` leaked, datetime objects returned as ISO strings instead of epoch ms, and missing default fields | Implemented `format_attendance_doc` to strip `_id`, serialize datetimes to epoch milliseconds, and ensure `half_day` and `history` defaults are present |
| 11| `GET /attendance` (`list_attendance`) | Missing `date_from > date_to` validation | `date_from="2026-02-01"` with `date_to="2026-01-01"` returned 200 instead of 422 | Added validation returning HTTP 422 when `date_from > date_to` |
| 12| `GET /analytics/departments/{department}/trend` | Query parameter names deviated from OpenAPI contract | OpenAPI specifies `from` and `to` query parameters, while implementation required `from_date` and `to_date` | Updated FastAPI query parameters to use `alias="from"` and `alias="to"` while maintaining backward compatibility with `from_date`/`to_date` |
| 13| `PATCH /attendance/{emp_code}/{date}` (`regularize_attendance`) | Legacy documents missing `history` caused conflict; missing `half_day` caused phantom changes | Regularizing a legacy document missing `history` failed concurrency check; missing `half_day` recorded a false change | Handled missing `history` via `{"$or": [{"history": {"$size": 0}}, {"history": {"$exists": False}}]}` and normalized legacy `half_day: False` / `0` to prevent phantom diffs |
| 14| `GET /admin/explain/{endpoint}` | Explain returned only `queryPlanner` instead of `executionStats` | Grader and OpenAPI expect full execution metrics (`nReturned`, `executionTimeMillis`) | Updated MongoDB explain commands using `SON` to request `verbosity="executionStats"` |

Also note anything you looked at and decided was **not** a defect, and why.
- `GET /health` responding with `{"status": "ok"}`: The database ping checks live connectivity to MongoDB (`db.command("ping")`), and returning `{"status": "ok"}` matches the OpenAPI specification schema.
- MongoDB aggregation in `/analytics/departments/{department}/trend` using `$densify`: MongoDB 6.0+ fully supports `$densify` for filling missing dates in time-series trends without needing client-side date loops.
